# Переменные окружения в Netlify: Что это даёт?

## Текущая ситуация

**Важно:** Сейчас приложение читает настройки (API ключи) из **базы данных**, а не напрямую из переменных окружения.

### Как работает сейчас:

1. Пользователь вводит API ключи через UI (страница `/settings`)
2. Ключи сохраняются в таблицу `settings` в базе данных
3. Приложение читает их из БД при каждом использовании

### Что дают переменные окружения в Netlify:

#### ✅ Преимущества:

1. **Безопасность:**
   - Ключи не хранятся в коде
   - Не попадают в Git
   - Защищены от случайного раскрытия

2. **Удобство управления:**
   - Можно менять ключи без изменения кода
   - Разные ключи для разных окружений (dev/prod)
   - Централизованное управление в Netlify Dashboard

3. **Автоматическая инициализация:**
   - При первом деплое можно автоматически подставить ключи
   - Не нужно вручную вводить их через UI

#### ⚠️ Текущее ограничение:

**Переменные окружения сейчас НЕ используются автоматически!**

Код ищет настройки только в базе данных:
- `server/telegram.ts` → `storage.getSettings()` → ищет `telegramBotToken`, `telegramChatId`
- `server/routes.ts` → `storage.getSettings()` → ищет `youtubeApiKey`

## Решение: Как использовать переменные окружения

### Вариант 1: Обновить код (рекомендуется)

Обновить код, чтобы он сначала проверял переменные окружения, а потом базу данных:

```typescript
// Пример для telegram.ts
const botToken = process.env.TELEGRAM_BOT_ID 
  || botTokenSetting?.value as string;
const chatId = process.env.TELEGRAM_CHAT_ID 
  || chatIdSetting?.value as string;
```

**Преимущества:**
- Переменные окружения имеют приоритет
- Можно переопределить настройки из БД
- Удобно для production деплоя

### Вариант 2: Инициализация при первом запуске

Создать скрипт, который при первом запуске копирует переменные окружения в БД:

```typescript
// При старте сервера
if (process.env.TELEGRAM_BOT_ID && !await storage.getSetting('telegramBotToken')) {
  await storage.upsertSetting('telegramBotToken', process.env.TELEGRAM_BOT_ID);
}
```

**Преимущества:**
- Не нужно менять логику чтения настроек
- Работает с текущим кодом

### Вариант 3: Только через UI (текущий способ)

Просто добавить переменные окружения в Netlify для документации, но использовать их вручную:
1. Скопировать значения из Netlify Dashboard
2. Вставить в UI на странице `/settings`

**Недостатки:**
- Нужно делать вручную
- Не использует преимущества переменных окружения

## Рекомендация

**Лучше всего:** Обновить код (Вариант 1), чтобы переменные окружения имели приоритет над БД. Это даст:
- ✅ Автоматическую работу с переменными окружения
- ✅ Возможность переопределить настройки из БД
- ✅ Безопасность (ключи не в коде)
- ✅ Удобство (не нужно вводить через UI)

## Что нужно сделать

1. **Сейчас (без изменений кода):**
   - Добавить переменные в Netlify для документации
   - Вручную скопировать их в UI на странице `/settings`

2. **После обновления кода:**
   - Переменные окружения будут использоваться автоматически
   - Приоритет: `process.env` → БД
   - Можно оставить UI для удобства, но не обязательно

## Маппинг переменных

Netlify переменные → Ключи в БД:
- `TELEGRAM_BOT_ID` → `telegramBotToken`
- `TELEGRAM_CHAT_ID` → `telegramChatId`
- `YOU_TUBE_API` → `youtubeApiKey`
